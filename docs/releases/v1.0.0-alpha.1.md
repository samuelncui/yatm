# v1.0.0-alpha.1

Status: Released September 15, 2026.

This Alpha introduces live directory management, saved content versions and one configurable Scan workflow to YATM's Tape/Volume archive management. Evaluate it with a complete installation backup. `v0.1.x` remains the stable release until a stable v1 is published.

## Installation and Upgrade

- [Installation, checksums and optional agent Skill](../operations/install.md)
- [v0.1.x migration, script adaptation and complete-backup recovery](../operations/migration.md)
- [Daily Library/Media use](../operations/library.md) and [live Locations](../operations/online-sources.md)

Select `--version v1.0.0-alpha.1` explicitly. Linux amd64/systemd is the automatic-install target. Each archive contains its version/commit, five offline-version-capable programs, installer, frontend, templates, documentation, Skill and dependency licenses. Companion SHA-256 files and `SHA256SUMS` identify the accepted archive bytes.

## Changes from v0.1.x

- File organization, tags and Note persist independently of content. FileVersions retain restore metadata and share independent archived copies by opaque signature.
- Locations browse actual directories and support physical organization; Library organization stays logical. Shared Files interactions include queries, grouped duplicates and compact local/backup status.
- Cross-directory Backup/Restore waitlists preserve selections, support nested inspection and explicit or recorded-time version choices.
- Scan combines signature, result and Preview policies. Analyze, Preview and integrity-check presets use the same pipeline. Copy verification reads against frozen prior facts; inventory publication does not claim health.
- Settings owns daily original and preferred Restore directories. Legacy source/target configuration registers Locations idempotently while administrator access boundaries remain configured explicitly.
- The installer presents the packaged migration guide, confirms interruption and the prepared report, retains complete backups/reports below the installation root, and preserves customized scripts, helpers and configuration. Cleanup verifies historical data against that backup before removing obsolete active artifacts.
- `yatm-migrate` provides explicit legacy conversion, validation, cleanup and backup-based historical Job repair. Data-format identities/revisions are independent of the software release number.
- Optional Skill installation delegates selection and confirmation to the pinned Skills CLI; cancellation or missing dependencies do not fail YATM installation.

Catalog and Job storage change during migration. Rollback restores a matching complete installation, not just the old executable. Legacy whole-object Library backups and their protobuf/key/signature encodings remain readable. Alpha APIs may evolve; [format and compatibility policies](../README.md#temporary-draft-compatibility-policy) describe support boundaries.

## Platform and Operational Limits

Linux amd64 is the primary target, with the packaged server/CLI workflow evidence above. macOS arm64 has local CLI and migration runtime evidence but remains an experimental deployment target. Other architectures have no native runtime acceptance. MySQL runtime remains untested. The official file backend does not validate physical Tape hardware, hardware encryption or physical end-of-Media behavior; those require separately assigned scratch Media. Installation success alone does not validate hardware or customized scripts.

The private legacy fixture contains retained Archive Jobs, not Restore Jobs; frozen legacy Restore paths are covered by synthetic semantic tests. Forced mid-migration interruption and malformed-package checks likewise use local test seams, separately from the real systemd installation runs.

Program replacement is non-atomic; interruption may leave a mixed tree and requires complete-backup recovery. Automatic upgrade covers contained SQLite layouts. Rollback does not undo newer filesystem or Media operations. Scripts remain environment-specific and need the documented Index/unmount adaptation before Tape use.

FreeBSD's ordinary-rename fallback may replace a destination created concurrently after its existence check; Linux/macOS use native no-replace behavior. Backup status is recorded knowledge, not a guarantee an offline copy can currently be read. Saved versions are not full directory snapshots.

Optional Skill installation depends on the pinned upstream Skills CLI and npm availability. Actual ordinary-user installation and repetition preserved the expected Skill bytes and user ownership. The upstream Skills CLI 1.5.0 picker can print `targetAgents.some is not a function` after Ctrl-C; YATM reports an optional-step failure and remains installed. Missing Node/npm was tested through local PATH lookup, not by removing remote host dependencies. These results are separate from service acceptance.
