# v1 Alpha 1

Status: v1 Alpha 1 prerelease.

v1 Alpha 1 adds live directory management, persistent saved content versions and a unified Scan workflow to YATM's Tape/Volume archive management. Alpha is intended for evaluation with a complete installation backup.

## Install and Upgrade

- [Release assets and source](https://github.com/samuelncui/yatm/releases/tag/v1.0.0-alpha.1)
- [Installation, checksums and optional agent Skill](../operations/install.md)
- [legacy upgrade, report approval and complete-backup recovery](../operations/migration.md)
- [Daily Library/Media use](../operations/library.md) and [live Locations](../operations/online-sources.md)

Select `--version v1.0.0-alpha.1` explicitly. The default installer continues to select the stable release. Linux amd64/systemd is the automatic-install target. Every archive includes its version/commit, five offline-version-capable programs, frontend, templates, documentation, Skill and dependency licenses. Companion SHA-256 files and `SHA256SUMS` identify the accepted archive bytes.

## Changes from legacy

- File organization, tags and Note persist independently of content. Saved FileVersions share independent archive copies by opaque signature, while retaining their own metadata and archive observations.
- Registered Locations browse actual directories and support guarded physical organization. Library organization remains logical. Cross-directory Backup/Restore waitlists retain their selections, with explicit versions and recorded-time Restore selection.
- Scan uses signature, result and Preview policies in one pipeline. Analyze, Preview and Verify CLI presets use this same Job kind. Media inventory publication is automatic; recorded-copy verification reads against frozen prior facts.
- Shared Files queries, duplicate-content groups, compact source/backup state and version previews expose the same content model through the UI and CLI.
- Settings owns daily source and preferred Restore directories. Legacy `paths.source`/`paths.target` convert idempotently to Locations; configuration retains administrator access boundaries and runtime/device settings.
- The installer checks upgrade eligibility, asks before interruption, takes a complete backup, requires legacy migration-report approval and preserves customized configuration/scripts/service files. Skill installation is optional, using the tested existing `skills@1.5.0` interactive tool.

legacy migration changes Catalog and Job storage; a downgrade restores the matching complete installation backup. Alpha 1 establishes the [published format families](../architecture/persistence.md#published-data-formats). Unpublished Draft catalogs/bundles and Draft Library JSONL headers are rejected before replacement. legacy whole-object backups, legacy protobuf, encryption keys, signature bytes and historical Job adapters retain their supported readers. Alpha APIs may evolve with release notes; published data keeps a supported forward path.

## Platforms and Limitations

| Platform | Alpha validation |
| --- | --- |
| Linux amd64 | Primary deployment; real systemd installation/upgrade, actual CLI workflows and official LTFS file backend. |
| macOS arm64 | Experimental archive; native CLI/server, migration, Volume/Preview and browser review. |
| macOS amd64, FreeBSD amd64 | Experimental, cross-built; native runtime not exercised. |
| Linux 386, arm64, arm v5/v6/v7, s390x | Experimental, cross-built; runtime not exercised. |

- Physical Tape hardware, hardware encryption and physical end-of-Media acceptance were not run for Alpha. Use separately assigned scratch Media for the [physical release gate](../operations/physical-tape-e2e.md).
- Program replacement is non-atomic. A failed activation keeps the service stopped; recovery restores the complete matching backup. Automatic upgrade supports contained SQLite layouts; external resources and MySQL require manual coordination. MySQL runtime remains untested.
- FreeBSD's ordinary-rename fallback can replace a destination created concurrently after its existence check. Linux/macOS retain their native no-replace behavior. No directory-level rollback is promised.
- Backup availability is recorded knowledge, not a promise that an offline copy can currently be read. Recovery performs content and Media identity checks. Saved versions are not complete directory snapshots.
- The production dependency audit reports no npm vulnerabilities and no reachable Go vulnerable call sites after focused upgrades. Non-reachable Go module findings remain; this is a scoped scan result, not a vulnerability-free guarantee.
- The frontend build retains a non-fatal file-browser chunk-size warning. Tape script integration depends on the installed LTFS implementation; validate customized mount/final-Index scripts before use.

Current architecture and operating guides own implemented behavior. Remaining proposals stay clearly marked Draft in the [documentation index](../README.md).
