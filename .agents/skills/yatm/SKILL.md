# YATM

Use the `yatm-cli` executable through a shell. Use the matching installed CLI help and JSON output as the operational source of truth. A mutating command reports what it would change under `--dryrun` and writes when the flag is omitted, so resolve a large or destructive operation with a report before running it. Catalog, Job bundle and Library backup formats have independent identities and format versions. Upgrade v0.1.x installations through the documented offline migration workflow before opening their data with v1.

Instant fields in CLI JSON use decimal strings with `_ns` suffixes: signed 64-bit Unix nanoseconds, not milliseconds or floating-point numbers. Keep them exact when processing or reusing output. Optional absent dates remain unknown; established zero sentinels remain zero. Restore `--before` accepts RFC3339 with an explicit timezone and preserves nanosecond precision; out-of-range dates are rejected. Durations and video offsets keep their named units.

## Connect

1. Run `yatm-cli --version` and `yatm-cli --help`, then run `yatm-cli <domain> --help` down to the relevant command.
2. Run `yatm-cli status` before other remote operations. Supply connection settings with global flags or the corresponding `YATM_*` environment variables.
3. Treat registered Location paths, Volume mount points, and Tape devices as paths on the YATM server.
4. Treat `--input`, `--output`, and `--basic-password-file` as paths on the machine running the agent.

## Operate

- Run read-only commands directly and interpret their JSON output. `--dryrun` is read-only as well.
- Run ordinary mutations when they are within the user's explicit request. A bare mutating command writes; `--dryrun` only reports.
- For a Job status check, request one progress result or one bounded list page per poll. Continue only at a cadence appropriate for the operation.
- When the result reports a busy device, missing Media, or another required physical action, report the current state and the exact action needed from the user.
- Location pages are live filesystem observations with optional File IDs. Browsing needs no prior analysis; no HTTP route or CLI command serves full original or archived file bytes. Library JSONL export/import and generated Preview assets remain available. Archive and Preview accept live Location or Library selections; preparation resolves identities and content. Restore selects versions and a confirmed authorized Location. The UI offers preferred Restore targets; CLI/API targets still use the same authorization checks, and preference is not permission. Review large selections before creating Jobs.
- `location create/update --use-mmap` enables mapped reads of that Location's original content in Archive and Scan; omission leaves it off. Location Ignore is stored with this unindexed configuration. `location update` replaces the complete configuration, so provide all desired flags and Ignore text when updating.
- `identical --source locations` selects complete Locations with repeatable `--root ID` values; it cannot narrow the query to a folder. `identical find` returns a disposable result ID and row counts. `identical groups` and `identical members` also return a result ID on their first page; later `--cursor` pages require `--result ID` to reuse the same complete search. An unavailable result fails; run Find again. `identical rows --result ID --offset N` reads a bounded row page, `identical positions --result ID --file-id ID` resolves file positions, and `identical close --result ID` releases it. Pass the same `--sort-key file-id|name|size` and optional `--order asc|desc` to rows and positions; defaults are File ID ascending, name ascending, and size descending. Sorting changes members within groups, not group order. Results expire after 30 minutes idle or a service restart. Keep/Merge still validate the current group independently of this browsing result.
- Scan is one pipeline. `analyze`, `preview` and `verify` are CLI presets, not separate Job kinds. `scan create` selects a signature policy (`known-only`, `fill-missing`, `force-read`) and result policy (`report`, `originals`, `inventory`, `verify`). `known-only` reuses valid facts or caches without hashing on a cache miss. Verification always reads against the saved baseline. Preview policy is `none`, `missing-only` or `regenerate-all`; sequential Media do not support Preview.
- `analyze create` collects selected input in basic, incremental or force mode. `--location-id` with optional `--path` values becomes Location selections; no paths selects the whole Location. All selected inputs are prepared into one Job manifest before content processing or Library publication. An input preparation error publishes no Library observations; a later content-processing failure retains previously completed Location results. A failed preparation is terminal for that Job, so a new Job is what scans all selected input again. Ordinary refresh creates no Job. `scan media` publishes inventory after complete validated observation, without Apply or an integrity guarantee. Read results with `scan results` and the attempt error with `job get`.
- `ls [PATH]` selects the Library root when PATH is omitted. `/Photos/2026`, `Photos/2026`, `./Photos/2026` and `library:///Photos/2026` all start from that root, never the client's working directory. `location://NAS/DCIM` selects `DCIM` below the registered root of the Location whose exact, case-sensitive display name is `NAS`; `location://NAS/` selects its root. `--server` still selects the YATM service. Missing or duplicate names fail; use `--location-id ID --path PATH` for duplicate names or stable ID-based scripts. `--file-id ID` remains available for Library. Supply at most one positional path, without ID selectors or a nonempty `--path`. Only `ls` accepts positional paths; other commands retain their existing syntax.
- Quote path operands containing spaces. Plain Library paths preserve punctuation literally; a colon alone does not select a URI, so `library:2026` names an ordinary Library directory. URI components are decoded once, so encode literal `%`, `?` and `#` as `%25`, `%3F` and `%23`. `.` and `..` are normalized within the selected root; traversal above it fails. Failed lookups never select another source or fall back to a local path. Resolution and listing share the global `--timeout` deadline.
- `ls` reads one directory completely and writes one JSON Lines message per batch; it is a minimal read that takes no page size or cursor, and `-l` adds attributes and `--status` adds content availability. `--query` switches it to a paged Search within the selected directory. `--recursive` also selects a paged Search over a Library subtree, even without a query expression. Both search forms take `--limit` and `--cursor`. Reads never collect files or create Jobs. Use explicit Scan with `known-only` and `originals` to add live files or directories to Library. `files get`, `files versions`, `files copies`, and `preview get` are independent detail reads; `preview get` reads one content signature, taking `--signature` directly or resolving `--version-id` or an entry (`--file-id`, or `--location-id` with `--path`) into one first. Preview generation still belongs to Scan.
- Legal UTF-8 filenames preserve literal backslashes, whitespace and control characters; quote operands for the shell. Non-UTF-8 names are unsupported. `ls` retains unreadable children as display-only rows with `error` and no actionable reference, drains all batches, then exits with the existing failure code and `code: incomplete`. Escaped unsupported names are display text, not paths. Directory and transport failures remain request failures. Never treat incomplete reads or failed Scan/Archive preparation as complete success.
- `du` explicitly measures all matching entries and selected directory contents, independently of Search pagination. Use `--file-id` or `--location-id`/`--path`, with optional `--query`; `--recursive` searches Library roots recursively. Results stream as JSON Lines and end with a deduplicated summary. Unknown/unreadable ranges retain known bytes but return nonzero; do not interpret that subtotal as complete. Use a suitable global `--timeout` (`0` disables the deadline) for large trees. Measurement does not collect, hash or create a Job.
- Before requesting Preview generation, check `preview capabilities` and the saved Preview settings. Generation requires an available native helper and explicit enablement; installing the optional helper does not enable it. Output options apply to new Jobs, while disabling generation lets running files finish and prevents later files from starting. Reading existing Preview assets remains available independently of generation enablement.
- `settings job --execution-json` holds the shared Job pipeline limits that new attempts run with: `read_batch` is the manifest page, and `read_buffer_max`, `write_buffer_max`, `write_batch_size` and `flush_interval_ms` are ACP's read buffer, result queue, result batch and result flush interval; the runner's result writer only persists the batches ACP hands over. A write batch must be at least 1 and no larger than the write buffer. Change these only when a large Job needs different batching, and read the stored group before assuming how a Job persists results.
- `mv`, `mkdir`, and `rm` share Library/Location organization rules and finish within the request, without creating a Job. Resolve the source and destination before mutation. Run them with `--dryrun` first when the selection is large or destructive: the report resolves the same targets and changes nothing, its entries stay `UNPROCESSED`, and a completed plan exits successfully. Planning failures, failed items and pending Library publication still exit nonzero. Results are JSON Lines with an item result and final summary; partial failure or interruption returns nonzero. Use a suitable request timeout; disconnecting cancels pending work. Inspect results and current paths before retrying, never blindly repeat completed mutations.
- `rm` moves Library entries to logical Trash or Location entries to the owned `.trash` directory. It does not permanently delete content. Location removal detaches the original association while retaining Library organization and archived versions. Use `mv` to move content out; reassociation requires an explicit Scan, annotation, or Archive. Trash occupies disk space and cannot be selected for Scan, Archive, or a Restore destination.
- `files import-positions` admits recorded Media content as independent Library Files under `Unforged/<Media>/...`; it copies no bytes. Without a selection it admits the whole Media, and `--media-id` restricts the admission to one Media. `--dryrun` reports how many entries would be added, how many are already in Library and how many have no signature, so obtain that count and add it only for a requested admission. Repeating an admission adds nothing because existing import paths are skipped.
- `files locate-original`, `location delete`, `media delete`, `job delete`, `library trim`, `library import`, `files remove-version`, and `identical keep`/`merge` also take `--dryrun`. A report is read-only; run the command without it only after the user has seen the resolved targets. `library import --dryrun` validates the whole snapshot and rolls it back. Library metadata backups never export or replace Settings.
- `verify create/run/entries` checks recorded Media content through actual reads in a Scan Job. Inspect typed findings; completion does not mean every copy is healthy.
- Restore links verified outputs according to the current binding and frozen version candidate, without displacing an existing original. Ignored outputs remain unlinked. Explicit `--allow-damaged-copies` permits complete damaged salvage, never a claim of verified restoration; do not enable it unless requested.
- `archive creation ID`, `restore creation ID` and `scan creation ID` read retained creation inputs only. The JSON response contains `request` and, when original inputs are incomplete, `unavailable_reason`. Resolve the stated missing inputs and review the selections/options through the normal pre-submit checks before an explicitly requested Create operation. Reading these inputs never creates work or changes the old Job; do not automatically submit the returned request.
- `job wait` has a timeout and succeeds for a completed Job even when its live phase is unavailable after restart. `QUEUED` is an admitted attempt waiting for shared Media, so keep waiting or explicitly cancel it; do not submit another Media operation or delete it. Waiting returns nonzero on terminal `FAILED` or idle `READY` with phase `UNSPECIFIED`, including the persisted error when present. No Job kind supports Job-level retry. Only an Archive or Restore Media operation failure or operator cancellation, including while `QUEUED`, returns to pre-Media `READY`, preserving the prepared manifest and error or cancel reason for another explicit Media operation. Initial preparation and Scan failure or cancellation remain terminal. Idle `READY` without an error still requires an explicit Media choice. Waiting does not choose Media, format, or continue writes automatically.
- `job log` reads one raw byte page; its JSON `logs` is plain text, and `offset` is the next byte offset as a decimal string. Use that offset for the next page and stop when `logs` is empty. `job log-lines ID` starts at the newest lines; `--direction older|newer` with a returned `--cursor` pages in either direction. `--level` and `--query` filter by log level and case-insensitive raw text. The server fixes the page size, so no limit flag is needed. Continue past empty filtered pages while the response reports more log in that direction.

Before File, Media, Job, or Location deletion, `files locate-original`, Library Import, Library Trim, or Tape FORMAT:

1. Run the relevant read-only commands to resolve the current target and state.
2. Show the user the exact IDs, paths, flags, device, Media identity, or input file that will be affected.
3. Obtain explicit confirmation for that resolved operation, showing the `--dryrun` report when one is available.
4. Execute one mutation command for that resolved operation.

For Tape FORMAT, run `yatm-cli media inspect tape` immediately before the write. Use the returned `identity` as both the requested barcode and the exact `--confirm-format` value. If the inspected Tape already has Library Media, report it and obtain separate authorization for any metadata deletion before formatting.

## Verify

After a mutation completes, run the corresponding read-only command and verify the resulting File, Media, Job, progress, Scan results, or service state. Report the command result and any remaining physical action.
